# Forbidden Lands Character Forge 2.0

## Независимое ревью, оценка стороннего ревью и план heavy luxury

Целевая среда: Foundry VTT 13.351, Forbidden Lands 13.0.5  
Исходная версия: 1.7.4 в `module.json`, 1.7.2 в `scripts/constants.js`  
Версия после переработки: 2.0.0

## 1. Итог

Исходный модуль был рабочим личным инструментом с удачно отделёнными данными и сервисами, но с перегруженным интеграционным слоем. Генератор имён и базовый подбор арта не требовали полного переписывания. Основной технический долг находился в трёх местах:

1. большой интерактивный интерфейс был реализован строковым `DialogV2` и ручным DOM-wiring;
2. Token HUD усиливался несколькими параллельными способами, включая патчи приватных методов, `MutationObserver` и каскад `setTimeout`;
3. учёт занятых изображений был простым журналом без жизненного цикла, очистки и защиты от параллельного выбора.

Выбран не косметический патч 1.7.x, а переход на 2.0.0. Сервисный слой сохранён и укреплён, интерфейс заменён полноценным ApplicationV2, а тяжёлые будущие функции получили стабильные точки расширения.

## 2. Оценка исходной архитектуры

### Сильные стороны

- Данные имён и культур вынесены из UI.
- Генерация имён, подбор арта и создание Actor уже были разнесены по сервисам.
- Существовал публичный API для Tavern Generator и других модулей.
- Поддерживались культура, пол, ветвящиеся папки и pairing портрета с токеном.
- Реестр занятых файлов решал реальную задачу повторов без изменения файлов на диске.
- Код был достаточно мал и понятен, чтобы рефакторинг можно было провести без уничтожения накопленных наборов.

### Главные проблемы

#### Высокий приоритет

- `DialogV2` фактически выполнял роль сложного приложения с состоянием, асинхронным сканированием и частичными обновлениями.
- Прямая замена `Actor.createDialog` не имела выключателя и безопасного отката при ошибке.
- Token HUD обрабатывался через штатные хуки, приватные методы, observer и задержки одновременно.
- Ручная правка автоматически созданного имени могла оставить прежний resolved gender и выбрать арт из неверной ветки.
- Повтор парного токена мог разрешаться раньше полного исчерпания пула.
- Реестр не освобождал файлы после удаления Actor или ручной смены его изображений.
- Выбор свободного изображения и запись результата не были атомарны для API и пакетных операций.
- Рекурсивный FilePicker scan выполнялся без отдельного кеширующего слоя.

#### Средний приоритет

- Версия дублировалась и расходилась между manifest и константой.
- Forge-флаги могли записываться Actor другого типа.
- JSON-настройки были доступны только как сырые большие строки.
- Не было локализации интерфейса.
- Неиспользуемый Handlebars-шаблон дублировал строковую реализацию окна.
- Отсутствовали диагностика, валидация наборов, история и пакетное создание.
- API не имел единых entry points для открытия интерфейсов, очистки кеша и обслуживания реестра.

## 3. Объективная оценка стороннего ревью

Стороннее ревью качественное и в основном технически точное. Оно правильно определило главный риск: не генерацию имён, а UI lifecycle и интеграцию с Foundry. Его можно оценить примерно на 8 из 10 как аудит и на 6 из 10 как готовый производственный план.

### Что определено верно

- расхождение версий;
- необходимость ApplicationV2 для основного Forge UI;
- риск прямого monkey-patch `Actor.createDialog`;
- избыточность TokenHUD-инъекций;
- stale resolved gender после ручной правки имени;
- запись Forge flags нецелевым Actor;
- преждевременный reuse парного токена;
- отсутствие очистки реестра;
- риск гонок при API и batch;
- необходимость кеша FilePicker;
- неиспользуемый шаблон настроек токенов;
- отсутствие локализации и нормальных редакторов настроек;
- полезность batch generation, diagnostics, history и расширенного API.

### Где приоритеты завышены

Ревью пометило несовпадение версии, большой DialogV2 и monkey-patch как P0. Это неверная классификация для уже работающего личного модуля.

- Расхождение `1.7.4/1.7.2` не блокирует работу. Это P2, максимум P1 для интеграционного API.
- Использование DialogV2 не является аварийным дефектом само по себе. Это P1 архитектурного риска и сопровождаемости.
- Monkey-patch `Actor.createDialog` требует безопасного wrapper и выключателя, но не является P0 без доказанного конфликта.
- TokenHUD-набор fallback-механизмов ближе всего к P0/P1, потому что может давать дубли и ломаться при обновлении, но исходный модуль уже имел dedupe и потому это всё же P1.

P0 следовало оставить только для ошибок, способных повреждать данные, блокировать создание Actor или стабильно ломать интерфейс в целевой версии.

### Что в ревью недоработано

- Не проведена чёткая граница между стабилизацией релиза и многомесячным продуктовым roadmap.
- Предложено слишком много самостоятельных подсистем без определения минимального вертикального среза.
- Не описана миграция существующих настроек и реестра как отдельный контракт.
- Недостаточно внимания уделено возвратным значениям API, предупреждениям и поведению `openSheet` для внешних модулей.
- Нет явного решения, как сохранить стандартный `Actor.createDialog` и одновременно дать независимый макросный вход.
- Не определено, какие heavy-luxury функции должны войти в 2.0, а какие требуют реальных пресетов, шаблонов Actor и согласования с Tavern Generator.
- Предложение немедленно вводить сложный reservation state избыточно для одиночного GM-клиента. Последовательная очередь вокруг операции `roll → create → mark` даёт достаточную защиту сейчас и оставляет путь к распределённым резервам позже.

### Вывод по стороннему ревью

Оно использовано как сильный список рисков, но не как готовая спецификация. Архитектурные выводы сохранены, приоритеты пересобраны, а scope разделён на реализованный фундамент 2.0 и дальнейшие продуктовые этапы.

## 4. Что реализовано в версии 2.0.0

### 4.1. Полноценный Character Forge на ApplicationV2

Новый файл: `scripts/apps/character-forge-app.js`  
Шаблон: `templates/apps/character-forge.hbs`

Вместо большой HTML-строки используется отдельное состояние приложения. Реализованы:

- имя, культура, пол, тип Actor и папка;
- генерация одного имени и список из восьми вариантов;
- корректный сброс resolved context при ручном редактировании имени;
- отдельный выбор арт-набора и его подпапки;
- независимый reroll арта;
- предпросмотр портрета и токена до создания;
- инспекция количества портретов, токенов и свободных файлов;
- ручное обновление кеша;
- сброс занятости выбранного набора;
- создание Actor;
- создание и открытие листа;
- создание с сохранением окна для следующего NPC;
- пакетное создание до 100 Actor;
- локальная история последних созданий;
- прямой переход к диагностике.

Состояние больше не хранится в hidden inputs. Асинхронные операции проходят через единый busy/status слой.

### 4.2. Безопасный compatibility wrapper стандартного создания Actor

Файл: `scripts/ui/create-dialog.js`

- Добавлена настройка отключения замены стандартного окна.
- Wrapper работает только если среди допустимых типов есть `character`.
- Любая ошибка Forge возвращает пользователя в оригинальный `Actor.createDialog`.
- Добавлен независимый entry point `game.fblCharacterForge.openForge()`.
- Создание через стандартное окно по-прежнему возвращает созданный Actor или `null`.

### 4.3. Asset Registry 2.0

Новый файл: `scripts/services/asset-registry.js`

- Запись хранит массив `kinds`, поэтому один файл может быть и portrait, и token без потери информации.
- Операция `roll → create → mark` выполняется в последовательной очереди.
- При удалении Actor его изображения освобождаются.
- При ручной смене `Actor.img` или `prototypeToken.texture.src` старые записи освобождаются, а новые пути регистрируются в известном арт-наборе Actor.
- Добавлены поиск и удаление записей-сирот.
- Добавлены статистика, экспорт и сброс отдельного набора.
- Старый формат `kind` мигрирует в новый `kinds` автоматически.

Это не распределённая блокировка между разными GM-клиентами. Для обычного мира с одним активным GM очередь закрывает практический риск. Межклиентские reservations остаются отдельным будущим этапом.

### 4.4. Кеширующий Asset Browser

Новый файл: `scripts/services/asset-browser.js`

- Все вызовы `FilePicker.browse` сосредоточены в одном сервисе.
- Передаётся фильтр расширений изображений.
- Результаты файлов и директорий кешируются.
- TTL настраивается от 0 до 120 минут.
- Есть ручная очистка через UI и API.
- Рекурсивный обход защищён от повторного посещения одной папки.

### 4.5. Исправление выбора арта

Файл: `scripts/services/art.js`

- Парный использованный токен больше не повторяется, пока существуют свободные токены, если повтор не разрешён условиями полного исчерпания.
- Сканирование вынесено в Asset Browser.
- Добавлены валидаторы арт-наборов.
- Поднаборы папок доступны в Forge UI.
- Сохранены прежние схемы `folder`, `portraitFolder`, `tokenFolder`, массивы файлов и ветки культура/пол.

### 4.6. Усиленная генерация имён

Файл: `scripts/services/names.js`

- Поддержаны weighted entries и weighted patterns в формате `{ value, weight }`.
- Добавлена проверка структуры наборов и повторов.
- Добавлена краткая память последних имён, уменьшающая немедленные повторы.
- Добавлен preview по сохранённому или несохранённому определению набора.
- Сохранена поддержка прежних полей и культурных aliases.

### 4.7. Редакторы конфигурации

Новые файлы:

- `scripts/apps/config-manager-app.js`;
- `templates/apps/config-manager.hbs`;
- `scripts/apps/token-name-patterns-app.js`;
- `templates/apps/token-name-patterns.hbs`.

Вместо одного глобального сырого JSON доступны отдельные менеджеры наборов имён и артов:

- выбор конкретного набора;
- форматирование JSON;
- валидация до сохранения;
- preview имён;
- добавление и удаление набора;
- возврат конкретного стандартного набора;
- импорт и экспорт конфигурации;
- переименование ключей наборов.

JSON сохранён как внутренний формат намеренно. Визуальный табличный редактор каждого массива имён потребовал бы отдельного большого продукта и не нужен для безопасного релиза 2.0.

### 4.8. Диагностический центр

Новые файлы:

- `scripts/apps/diagnostics-app.js`;
- `templates/apps/diagnostics.hbs`.

Показываются:

- версии модуля, Foundry и системы;
- количество и ошибки наборов имён;
- количество и ошибки наборов артов;
- размер реестра и число сирот;
- размер кеша и его TTL;
- действия очистки кеша и реестра;
- копирование отчёта.

### 4.9. Пакетное создание и шаблоны Actor

Файл: `scripts/services/actors.js`

- `createActorsBatch` создаёт Actor последовательно и возвращает результаты и ошибки; сбой UI-callback прогресса не превращает уже созданного Actor в ложную ошибку.
- Поддержан `templateUuid`: Forge клонирует Actor-шаблон и заменяет имя, арт и целевые параметры.
- Поддержаны пользовательские flags и папка назначения.
- Для вызовов внешнего модуля лист по умолчанию не открывается.
- Forge flags пишутся только Actor типа `character`.
- API возвращает warnings, resolved name set, gender, art set и art error.

Создание напрямую внутри Compendium не включено: это отдельный режим назначения коллекции и требует тестирования поведения папок и прав конкретной версии Foundry.

### 4.10. Token Names 2.0 foundation

Файлы:

- `scripts/services/token-names.js`;
- `scripts/ui/token-config.js`;
- `scripts/ui/token-hud.js`.

- Удалены патчи `_postRender`, `bind`, глобальный `MutationObserver` и каскад таймеров.
- Используются `renderApplicationV2`, `renderTokenConfig` и `renderTokenHUD`.
- Кнопка HUD появляется только у токена с включённым случайным именем.
- Обычный клик создаёт новое имя выбранной культуры.
- Alt-клик использует случайную культуру.
- Ctrl-клик возвращает имя Actor.
- В TokenConfig добавлена кнопка preview.
- Случайное имя не применяется к обычному токену, если wildcard был отключён, но старый флаг остался.
- Массовый reroll контролируемых токенов доступен через API.

Политики `once/on every drop/on combat/manual` и отдельный визуальный lock оставлены на следующий этап. Схема уже имеет совместимые флаги для дальнейшего расширения.

### 4.11. Локализация и manifest

Добавлены:

- `lang/ru.json`;
- `lang/en.json`;
- системная зависимость Forbidden Lands 13.0.5;
- явная максимальная совместимость Foundry 13;
- единая версия 2.0.0;
- получение runtime version из manifest для API.

## 5. Изменения публичного API

Старые основные вызовы сохранены:

```js
game.fblCharacterForge.generateName("novand", "male");
game.fblCharacterForge.generateNameDetailed("sangren", "female");
game.fblCharacterForge.rollArt("humanByCultureGender", context);
game.fblCharacterForge.createActor(options);
```

Добавлены:

```js
game.fblCharacterForge.openForge();
game.fblCharacterForge.openDiagnostics();
game.fblCharacterForge.openNameSetManager();
game.fblCharacterForge.openArtSetManager();
game.fblCharacterForge.openTokenNamePatterns();

game.fblCharacterForge.createBatch({
  count: 10,
  cultureKey: "novand",
  gender: "random",
  artSetKey: "humanByCultureGender",
  folderName: "Случайные новандцы",
  createFolder: true
});

game.fblCharacterForge.createActor({
  templateUuid: "Compendium.world.actor-templates.Actor.xxxxxxxxxxxxxxxx",
  cultureKey: "sangren",
  folderName: "Сангренские NPC",
  openSheet: false
});

game.fblCharacterForge.rerollControlledTokenNames();
game.fblCharacterForge.clearArtCache();
game.fblCharacterForge.getArtCacheStats();
game.fblCharacterForge.getAssetRegistryStats();
game.fblCharacterForge.cleanupAssetRegistry();
game.fblCharacterForge.exportAssetRegistry();
```

`createActor` возвращает:

```js
{
  actor,
  nameDetails,
  nameSetKey,
  gender,
  artSetKey,
  art,
  artError,
  warnings
}
```

## 6. Миграция с 1.7.4

Миграция выполняется на `ready`.

- Существующие наборы имён и артов не заменяются целиком.
- Недостающие стандартные наборы добавляются.
- Дополнения к стандартным именам объединяются без дублей.
- Недостающие стандартные культурные папки добавляются.
- Недостающие шаблоны pairing токенов добавляются.
- Старые записи `{ kind }` преобразуются в `{ kinds: [] }`.
- Устанавливается `settingsSchemaVersion = 2`.

Перед обновлением всё равно разумно сделать обычный backup мира. Модуль не переименовывает и не удаляет файлы изображений на диске.

## 7. Что сознательно не включено в 2.0.0

### 7.1. Полноценные культурные профили

Связка `culture → names → art → token mode → weights → tags` полезна, но требует миграции двух существующих моделей данных в третью. В 2.0 сохранены совместимые `nameSetKey/cultureKey` и art branches. Профили следует вводить после проверки нового UI.

### 7.2. Галерея всей арт-библиотеки

Текущий Forge показывает выбранную пару, статистику и подпапки. Полная виртуализированная галерея с сотнями изображений, blacklist, favorite и ручным pairing требует отдельного индексного UI.

### 7.3. Ролевые пресеты

`Тавернщик`, `солдат`, `стражник`, `дворянин` должны задавать не только имя и subset, но и Actor template, items, ownership и flags других модулей. Сначала нужны реальные шаблоны пользователя и контракт с Tavern Generator.

### 7.4. Создание прямо в Compendium

Клонирование из Compendium реализовано через `templateUuid`. Запись результата прямо в pack оставлена до отдельного теста Foundry 13.351.

### 7.5. Межклиентские reservations

Текущая очередь защищает операции одного клиента. Одновременная работа нескольких GM требует socket-based reservation protocol или общего document-хранилища. Для личного мира это не оправдано до появления фактической проблемы.

### 7.6. Визуальный редактор массивов имён

Текущий per-set JSON editor уже устраняет риск редактирования всей мировой базы одним огромным полем и даёт валидацию. Drag-and-drop редактор тысяч значений имеет низкую отдачу по сравнению с галереей артов и пресетами.

## 8. Следующий roadmap

- проверить стандартное создание Actor из sidebar и folder context menu;
- исправить только реальные несовместимости, не расширяя scope;
- собрать консольные ошибки и диагностический отчёт.

- постоянный индекс с timestamp и checksum конфигурации;
- виртуализированная галерея;
- фильтры культура, пол, subset, used/free;
- ручной выбор portrait/token;
- favorite, excluded и broken path;

- отчёт по неиспользованным и битым файлам.

- единый профиль культуры;

- менеджер пресетов;
- интеграция Tavern Generator без знания внутренней структуры Forge.

### 2.3.0: Token Names policies

- lock/unlock в HUD;
- массовые действия для выбранных токенов;
- отдельное сохранение rolled state и prototype configuration;
- восстановление предыдущего ручного имени, а не только имени Actor.

### 2.4.0: Production batch tools

- прогресс-окно с отменой;
- отчёт Journal/CSV;
- создание в world или pack;
- распределение пола по ratio;

- transaction report при частичном сбое.

## 9. Приёмочный тест-план

### Основное окно

Полноценный runtime-тест внутри установленного Foundry VTT из этой среды невозможен. Наиболее вероятные полевые риски находятся в конкретной DOM-разметке TokenConfig/TokenHUD и в нюансах вызова стандартного `Actor.createDialog` системой. Для них оставлены fallback, выключатель и независимый макросный вход.

## 11. Макросы для запуска

Открыть Forge:

```js
game.fblCharacterForge.openForge();
```

Создать десять случайных персонажей:

```js
await game.fblCharacterForge.createBatch({
  count: 10,
  cultureKey: "random",
  gender: "random",
  artSetKey: "humanByCultureGender",
  folderName: "Случайные NPC",
  createFolder: true
});
```

Диагностика:

```js
game.fblCharacterForge.openDiagnostics();
```

Перегенерировать имена выделенных токенов:

```js
await game.fblCharacterForge.rerollControlledTokenNames();
```
